## 1️⃣ Cloudflare → 建 R2 bucket

1. 登录 https://dash.cloudflare.com → 首次会让你创建一个域（Zone）。
   **随便填一个域名即可**，不必真有；也可以直接跳过走 R2 页面。
2. 左侧选 **R2**（Overview 页可能有 "Get started" 引导）
3. 点 **Create bucket**
   - Bucket name：`news-etl-audio`（全局唯一，被占用就换个名字）
   - Location：`Automatic`（或选 Asia Pacific）
   - Storage class：默认
4. **创建公开域名**（关键，否则 App 拿不到音频直链）
   - R2 → 你的 bucket → **Settings** → **Public Access** → 启用
   - 建议绑定自定义域名；若暂时没有域名，可用 R2 默认的 `r2.dev` 域名（限速但够用）
   - 记录下这个地址，形如 `https://news-etl-audio.<accountid>.r2.dev`
5. **创建 Access Key**
   - R2 左侧 → **Manage R2 API Tokens** → **Create API Token**
   - 权限选 **Object Read & Write**
   - 选中你刚建的 bucket
   - 创建后会显示 **Access Key ID** 和 **Secret Access Key**
   - ⚠️ **Secret 只显示这一次**，务必马上复制保存

**记下这3 个值**（填 GitHub Secrets 用）：
```
R2_BUCKET            = news-etl-audio
R2_ACCESS_KEY_ID     = 你的 Access Key ID
R2_SECRET_ACCESS_KEY = 你的 Secret Access Key
R2_ENDPOINT          = https://<accountid>.r2.cloudflarestorage.com
R2_PUBLIC_BASE       = https://news-etl-audio.<accountid>.r2.dev
```
> accountid 在 R2 页面右侧能看到，形如一串 32 位十六进制。

## 2️⃣ Neon → 建数据库

1. 登录 https://console.neon.tech → GitHub 一键登录（最快）
2. 点 **New Project**
   - Project name：`news-etl`
   - Postgres version：默认最新
   - Region：**选离国内近的** —— `Asia Pacific (Singapore)` 或 `Tokyo`
   - Plan：**Free**
3. 创建后自动给你一个连接串，形如：
   ```
   postgresql://user:password@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```
   在 **Connection Details** 面板里，**不要用 pooled 连接串**（要用 `-pooler` 之外的直连地址）
4. 复制完整串

**记下**：
```
DATABASE_URL = postgresql://user:password@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
```

> 注意密码里如果有特殊字符，需要 URL 编码。

## 常见问题

**Q: R2 的 `r2.dev` 域名限速，App 用户多会不会有问题？**
限速是每账户共享，但个人 App 的量级完全够。正式做大了再绑自定义域名即可。

**Q: 免费额度会超吗？**
- R2：10GB，我们每月约 1GB → 可用 10 个月
- Neon：0.5GB，存的是元数据 + 时间轴（每天约 1MB）→ 可用很久
- Gemini：1500次/天，我们 70 次 → 富余 20 倍

**Q: 60 天后定时任务会停吗？**
GitHub 会对**无活动**的仓库禁用定时任务。我在 workflow 最后加了自动提交运行记录，
每次跑完都会产生 commit，所以仓库一直活跃，不会被禁用。

**Q: 如果 GitHub Actions 出问题，备用方案？**
随时可以手动在本地跑（见 README），或换用国内云 VPS —— 数据库和音频都在外部存储，
迁移只需改API 的读取源，不用搬数据。
